# BUGSMASHER CTO-Level Codebase Audit — 2026-06-17

## Executive Verdict

BUGSMASHER is a strong pre-production browser game with real system extraction, a large unit test suite, and a distinctive product hook. It is not production-grade for competitive or commercial launch. The gap is not visual polish; the gap is trust boundaries, Firebase enforcement, end-to-end verification, and operational rigor.

**Overall score: 7.5 / 10.** Portfolio quality is high. CTO-grade launch confidence is still blocked by security and validation architecture.

## Highest-Priority Issues

1. **Cloud save and leaderboard trust is client-authoritative.** Direct client writes must not be the authoritative path for competitive data.
2. **The Firestore trigger is after-the-fact validation.** It cannot prevent the original write; invalid documents must be denied by rules or written only by server code.
3. **A checksum salt in browser code is not a secret.** Treat it as local corruption detection only, not anti-cheat.
4. **Vite was configured to expose `GEMINI_API_KEY` to client bundles if referenced.** This audit removed that build-time define.
5. **Cloud Functions had an insecure fallback checksum salt.** This audit changed Functions startup to fail closed when `CHECKSUM_SALT` is missing.
6. **Tests do not prove Firebase rules/functions behavior.** Add emulator tests for save, leaderboard, and invalid write paths.
7. **Broad Google Workspace OAuth scopes are requested up front.** Use incremental auth and remove scopes until features need them.
8. **Global console suppression can hide security regressions in tests.** Security warnings should be asserted in targeted tests, not globally muted.
9. **No automated dependency/security gate.** Add scheduled audits and high/critical blockers after initial triage.
10. **No production performance budget.** Add browser-level frame budget smoke tests for representative waves.

## Best Possible Plan to Reach 10/10

### P0 — Trust Boundary Hardening (1–2 days)
- Deny direct client writes to global leaderboard and authoritative cloud saves.
- Introduce callable/HTTPS Functions for save and score submission.
- Add server-side schema validation, score/wave bounds, rate limiting, App Check, and audit logs.
- Add Firebase Emulator tests proving invalid direct writes fail and valid server writes pass.

### P1 — Verification Backbone (1–2 days)
- Add coverage thresholds for new security modules.
- Split noisy environment warning suppression from security warning assertions.
- Add Playwright smoke tests for start game, pause/resume, settings, save/load, and leaderboard display.
- Add dependency audit / OSV / Dependabot workflows.

### P1 — Runtime and Product Observability (1 day)
- Wire analytics events to real provider behind consent/config.
- Add structured telemetry for wave completion, death reason, FPS degradation, audio availability, and save failures.
- Build a lightweight operational dashboard.

### P2 — Performance and Accessibility Proof (1–2 days)
- Add automated Lighthouse/a11y checks for menu flows.
- Add frame-budget benchmark scenarios for high-wave bug counts and reduced-motion mode.
- Profile Canvas hot paths and reduce allocations in render loops.

### P2 — Maintainability Cleanup (ongoing)
- Replace static managers with injected session services where practical.
- Continue removing UI `any` casts and isolate Google Workspace integration behind typed adapters.
- Add PR templates with security/perf/test checklist and architectural decision records for trust-boundary changes.

## Risks and Unknowns

- No production Firebase project was exercised during this audit.
- No real browser profiler trace was captured in this terminal-only pass.
- NPM audit availability can be environment-dependent; CI should run it in GitHub and on a schedule.
- Google Workspace feature risk depends on actual OAuth consent-screen configuration and production CSP, which were not validated here.

## Changes Made in This Audit Pass

- Removed the Vite `process.env.GEMINI_API_KEY` client-build define.
- Made Cloud Functions checksum validation fail closed when `CHECKSUM_SALT` is missing.
- Replaced `any` with `unknown` in core checksum APIs and server error handling touched in this pass.
- Fixed the offscreen environment cache so static and periodic layers no longer share one corruptible canvas.
- Added checksum tests for deterministic key ordering, mutation rejection, and missing checksum rejection.
- Added offscreen cache regression tests for layer isolation and dimension invalidation.
- Added root deploy scripts for Functions and full Firebase deploy orchestration.
